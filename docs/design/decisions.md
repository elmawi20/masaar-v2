# Masaar Clinic System — Architectural & Product Decision Log

This log records all formal decisions, clarifications, and architecture agreements made throughout the design and build phases.

---

## Decision Log

| ID | Date | Decision | Reason | Spec Section / Rule |
|:---:|:---:|---|---|:---:|
| **DEC-001** | 2026-10-25 | Single source of truth is established as `docs/FEATURES-v2.1.md`. Older documentation is moved to `docs/OLD-FEATURES.md` for historical text reference only. | Prevents contradictory requirements and ensures unified system behavior. | Spec §0 |
| **DEC-002** | 2026-10-25 | Currency values stored strictly as integer piasters (e.g. 450.00 EGP = 45000 piasters). | Eliminates floating-point rounding errors in financial transactions and balance tracking. | Spec §0.4 |
| **DEC-003** | 2026-10-25 | Zero hard-deletion of business data (patients, appointments, receipts, expenses, notes, staff). Records are deactivated, voided, or cancelled. | Ensures full legal, clinical, and financial auditability. | Spec §0.3 |
| **DEC-004** | 2026-10-25 | Timestamps stored in UTC; displayed in `Africa/Cairo` time. Local appointment dates use clinic calendar days. | Guarantees timezone consistency across servers while showing local Egyptian clinic time. | Spec §0.5 |
| **DEC-005** | 2026-10-25 | Calculated values (balances, remaining sessions, package status) are never stored in the database. | Prevents data desynchronization bugs and race conditions. | Spec §0.6 |
| **DEC-006** | 2026-10-25 | Exclusion constraints (`btree_gist`) in PostgreSQL enforce non-overlapping bookings for clinicians and beds directly at the database engine level. | Prevents double bookings even during simultaneous concurrent front-desk actions. | Spec §5.2 |
| **DEC-007** | 2026-10-25 | Two-step verification (TOTP Authenticator app) mandatory for all staff logins; no SMS OTP. | Provides zero-cost, offline-capable, high-security authentication without third-party SMS API fees. | Spec §15.2 |
| **DEC-008** | 2026-10-25 | Waitlisted appointments release bed and clinician calendar slots, but hold a package session against `availableSessions` until scheduled or cancelled. | Prevents overbooking package sessions while freeing physical beds on calendar. Full overlap checks re-run when scheduled. | Spec §5.2, §5.5 (Q-01) |
| **DEC-009** | 2026-10-25 | Multi-session packages in v1 cover Physiotherapy or Nutrition only; Consultant Assessments are billed as standalone single visits. | Clarifies package scope and avoids pricing ambiguities with assessment visits. | Spec §2, §7 (Q-02) |
| **DEC-010** | 2026-10-25 | Owner account default commission is set to `none` (0%), avoiding artificial clinic expenses, but remains configurable if desired. | Avoids clinic accounting distortion from owner clinical sessions. | Spec §1, §3, §11 (Q-03) |
| **DEC-011** | 2026-10-25 | Cash shift closing is tracked per user ID. If a receptionist attempts to log out or switch user with an active unclosed cash shift, system prompts them to complete closing first. | Maintains personal cash drawer accountability on shared workstations. | Spec §8.4, §15.1 (Q-04) |
| **DEC-012** | 2026-10-25 | Every price change (before or after payment) writes an audit log entry with `oldPrice`, `newPrice`, reason, and user id. Receptionist can adjust price at initial booking before payment; changing price after payment exists is Owner/Manager only. | Gives front desk flexibility for upfront discounts while providing complete audit traceability and preventing financial manipulation after payment. | Spec §1.1, §2, §5.1, §8.3 (Q-05) |
| **DEC-013** | 2026-10-25 | Clinician "Covering access" is strictly valid only for the active login session (maximum 12 hours or until logout/idle lock). Subsequent sessions require entering a fresh reason. | Protects patient privacy by preventing indefinite access grants to non-assigned files. | Spec §1.1 (Q-06) |
| **DEC-014** | 2026-10-25 | Patient phone dual model: Adults require own unique mobile (`01XXXXXXXXX`, DB partial unique index `WHERE mobile_phone IS NOT NULL`). Dependents (child/elderly) check "Uses guardian's phone" requiring guardian name, relation, and guardian phone (Egyptian mobile format); own mobile left empty; guardian phone may repeat across dependents. Patient search by phone matches both `mobilePhone` and `guardianPhone`. | Accommodates families and pediatric patients while maintaining strict unique primary identifiers for adult patients and enabling complete family search. | Spec §4.1, §4.2 (Q-07) |
| **DEC-015** | 2026-10-25 | A cash refund reduces the expected cash closing of the specific user who physically handed out the cash. | Ensures physical cash drawer balance matches expected drawer cash for the user on duty. | Spec §8.3, §8.4 (Q-08) |
| **DEC-016** | 2026-10-25 | 24-hour clinical note edit window is calculated from the exact initial save timestamp (`completedAt`). | Provides a deterministic and tamper-resistant countdown for clinical note locking. | Spec §9.2 (Q-09) |
| **DEC-017** | 2026-10-25 | Annual receipt number sequence (`INV-YYYY-00001`) rolls over on January 1st at 00:00:00 Cairo local time (`Africa/Cairo`). | Aligns receipt sequence numbering with the clinic's local operating and financial year in Egypt. | Spec §8.2 (Q-10) |
| **DEC-018** | 2026-10-25 | Dual-phase late arrival detection: visual dashboard alert if current time exceeds `startTime + 10 min` unarrived; when checked in, `lateMinutes` stored and clinician notified. | Gives receptionist early awareness of running late, and alerts treating clinician immediately upon arrival. | Spec §5.5, §14 (Q-11) |
| **DEC-019** | 2026-10-25 | InBody height pre-fills from patient profile or previous consultation, but remains freely editable. | Saves nutritionist entry time for adults while supporting pediatric growth tracking and corrections. | Spec §9.4 (Q-12) |
| **DEC-020** | 2026-10-25 | Expenses included in a completed cash closing are locked from receptionist edit/void. Subsequent changes require Owner/Manager void with audit reason. | Protects historical closed cash shifts from retroactive tampering. | Spec §1.1, §8.4, §10 (Q-13) |
| **DEC-021** | 2026-10-25 | Bed reservations persist through the full scheduled duration even if a session is completed early. | Prevents calendar slot jumping and double-booking collisions; front desk may reschedule or book walk-ins manually if needed. | Spec §5.1, §5.2, §9.1 (Q-14) |
| **DEC-022** | 2026-10-25 | WhatsApp messaging consent (`whatsappConsent`) is a separate boolean toggle from mandatory medical data processing consent (`dataConsent`). If false, WhatsApp buttons show "Opted out". | Respects patient communication privacy rights without blocking clinical registration. | Spec §4.1, §6 (Q-15) |
| **DEC-023** | 2026-10-25 | Balance formula updated: $\text{balance} = \max(0, \text{owed} - (\text{non-voided payments} - \text{refunds}) - \text{write-offs})$, where $\text{owed}$ is package price (or value of completed sessions if package is cancelled), or appointment price. | Correctly handles financial liability for cancelled packages and eliminates negative balances. | Spec §8.1 |
| **DEC-024** | 2026-10-25 | Specification version bumped from v2.1 to v2.2 at `docs/FEATURES-v2.2.md` as the active single source of truth. | Codifies all design clarifications and decision resolutions into the master spec. | Spec §0 |
| **DEC-025** | 2026-10-25 | Rule IDs are permanent. Never renumber. New rules get the next free number in their section; removed rules keep their ID marked (removed). | Ensures persistent traceability across tests, permissions, state machines, and code. | Spec §0 (Task 1.03) |
| **DEC-026** | 2026-10-25 | Commission payout voiding is restricted to Owner and Manager with mandatory reason and full audit logging. Voiding automatically voids the linked `Doctor commission` expense voucher and releases linked completed sessions via the partial unique index `idx_unique_active_paid_session` so they can be recalculated in a future payout run. | Allows administrative correction of mistakenly processed commission runs without allowing duplicate payouts. | Spec §11 (R-11-4, Q-16) |
